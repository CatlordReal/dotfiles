
## Codex Inbox — parallel rollout

Use the installed `codex-inbox` skill at `${CODEX_HOME:-$HOME/.codex}/skills/codex-inbox/SKILL.md` for task communication when its private host configuration is available. Main agents publish overall task completion (green), blockers (red), required replies (yellow), optional preferences (blue), and meaningful intermediate progress (purple, silent by default). Green is reserved for completion of the entire user-requested task. Intermediate steps and completed subtasks are progress, never green dots or completion alerts in Inbox or ntfy. Keep the same substantive information in the current ChatGPT/Codex chat. Inbox is a separate compact conversation; do not mirror the normal Codex transcript. Only actual user questions belong in the request box; blockers, progress, and success belong in the Inbox conversation. Never infer a human approval request from a hook or delay. Subagents report to parents to avoid duplicate notifications.

At the start of every main-agent work turn, before investigation or tool work, publish current status using the installed helper even when no user input is needed: `python3 "${CODEX_HOME:-$HOME/.codex}/skills/codex-inbox/scripts/publish.py" status "Working" --preview "Starting work"`. Use the exact `CODEX_THREAD_ID`; never register unused Codex chats or publish for subagents. Use a brief task-specific status when known. Status updates only the current activity and summaries: it must never create a purple transcript message or notification, even if progress notifications are enabled. Update status when the work changes; do not echo the user's request as a progress notification. Reserve `progress --report` for a meaningful intermediate result worth retaining in the conversation. Routine starts, plans, tool narration, and "fixing xyz" belong in status. Do not mark idle chats active or send artificial keepalives. Missing configuration or delivery failure must not stop authorized work.

Keep all current ntfy question/completion notifications active alongside Inbox until the user explicitly declares Inbox ready. Inbox mutes affect Inbox only during this parallel rollout. Check private queued Inbox deliveries at a meaningful milestone; failures must not interrupt authorized work or silently replace the original chat. Linux uses its own host-bound credentials and the penguin prefix. Never commit tokens, device tokens, private messages, or runtime databases to dotfiles.
